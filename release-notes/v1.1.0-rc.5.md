## RKE2 v1.36.5-rc2 with Cilium 1.20.2, Gateway API, and audit fixes

`v1.1.0-rc.5` builds on `v1.1.0-rc.4` (bastion-only floating-IP probe,
control-plane egress check). It moves to Cilium 1.20, adds optional Cilium
load-balancer features and Gateway API, and fixes the findings of a full
project audit.

### RKE2 v1.36.5-rc2 and Cilium 1.20.2

- RKE2 moves to the release candidate `v1.36.5-rc2+rke2r1` (Kubernetes
  1.36.5), which bundles Cilium 1.20.2 (`rke2-cilium` 1.20.200). Validation
  accepts this exact candidate only, not pre-releases in general.
- The bastion bootstrap cache pins the release tarball checksum and its 27
  RKE2 system images by index digest. `scripts/rke2-cache-inventory.py`
  regenerates the list; DEVELOPMENT.md documents the swap to GA v1.36.5.
- The existing Cilium settings (native routing, kube-proxy replacement,
  egress gateway, L2 announcements) carry over unchanged.
- Cilium 1.20 fixes a load-balancer frontend collision when a frontend IP
  equals the node IP (the Node-LB datapath), L2 announcements dropping
  `externalTrafficPolicy: Local` traffic, and L2 announcer re-evaluation on
  frontend changes.
- `deploy update` can now actually upgrade RKE2. The version is recorded in
  the state journal after every server is upgraded, and the upgrade guard
  orders `v1.36.5-rc2` before GA `v1.36.5`.

### Optional Cilium load-balancer features

- Node-LB datapath Services default `spec.trafficDistribution` to
  `PreferSameNode` when the user Service sets none. Services from earlier
  releases are updated in place without withdrawing the published address.
- New optional, creation-time `InSpaceCluster.spec.network` settings:
  `loadBalancerAlgorithm` (`random` or `maglev`) and `serviceTopology`.
  Cilium honors `PreferSameNode`, `PreferSameZone`, and `PreferClose` only
  with `serviceTopology: true`. Deploy options: `load_balancer_algorithm`,
  `service_topology`.
- A Cilium configuration drift check (`cilium_drift_checker_config_delta`)
  runs after E2E init and during `deploy update`, and names any agent that
  has not applied its configuration.
- Private Cilium L2 VIPs support `externalTrafficPolicy: Local`.

### Optional Gateway API through Cilium

- New clusters can set `spec.network.gatewayAPI.enabled: true` (deploy:
  `gateway_api_enabled: true`) to use Cilium's Gateway API implementation
  through the `cilium` GatewayClass. It needs an RKE2 release that bundles
  Cilium 1.20. Traefik and ingress-nginx stay disabled; Gateway API needs
  neither.
- Below RKE2 v1.37 the pinned Gateway API v1.6.1 standard CRDs ship inside
  `inspace-cluster-controller` and are installed before RKE2 starts. From
  v1.37, RKE2's `rke2-gateway-api-crd` chart owns them and `deploy update`
  hands them over without deleting them.
- A Gateway can use the paid public NLB or a private Cilium L2 VIP.
  Node-LB modes do not support Gateways.

### Bootstrap controller fixes

- A malformed-create rollback and teardown no longer delete a VM before its
  auto floating IP is recorded, so they cannot leak the address or wedge.
- Re-running `init` after Karpenter or Node-LB workers exist no longer fails
  with a node-firewall assignment drift error.
- `--until-ready` and `--delete` retry transient network failures of API
  reads instead of exiting.
- Control-plane and bastion cloud-init checks (Ubuntu sources, bash login
  shell, systemd-resolved) now fail the boot when violated; they were no-ops
  under `set -e`. The rendered cloud-init changes.

### Karpenter provider fixes

- A VM delete or base-firewall detach that fails without committing is
  re-sent after three spaced reads still show the exact owned resource.
  Before, the VM stayed billed or every later launch was blocked.
- A NodeClaim on a known-bad floating IP is replaced at once
  (`InsufficientCapacity`) instead of waiting for the registration timeout.
- The shared firewall lock is held only around the mutation, and VM delete
  drops a redundant absence proof, so each worker delete is about a minute
  faster.
- Worker bootstrap checks now fail the boot when violated.

### Node load balancer fixes

- Node-LB Services that claim reserved host or cluster ports (SSH, etcd, the
  API server, RKE2, kubelet, the NodePort range, Cilium) are rejected with a
  `NodeLoadBalancerReservedPort` warning. Existing Services on such ports
  are withdrawn after the upgrade.
- Firewall delete, assign, and unassign requests that failed without
  committing, a Service arriving during ICMP firewall deletion, and a
  definitively rejected firewall create now recover automatically instead
  of needing an operator.
- Standard NLB removal requeues at a fixed short delay, and Node-LB cleanup
  finalizes in the pass that proves firewall absence.

### CSI driver fix

- A resize InSpace rejects permanently (quota or invalid size) fails at once
  with InSpace's reason as `InvalidArgument`, so the PVC shows why. Before,
  it retried forever as "temporarily unavailable".

### E2E and deploy

- E2E teardown overlaps independent cleanups, and cloud-init waits are
  bounded (40 minutes for control planes, 10 for workers).
- The deploy control-plane egress and cloud-init checks retry SSH transport
  failures only.
- New deploy inventory option `os_version`; an existing cluster keeps the
  release it was built with. The example inventory uses a current version.

## Upgrade notes

- The control-plane cloud-init bytes change (RKE2 version and bootstrap
  checks), so existing fixed VMs are not adopted by a re-run of `init`; use
  `deploy update` for RKE2 upgrades.
- `loadBalancerAlgorithm`, `serviceTopology`, and `gatewayAPI` are fixed at
  cluster creation.
- Node-LB Services on reserved ports are withdrawn after the upgrade. Move
  them to an allowed port first.
- Apply the CRD chart from this candidate before the workload chart.
