## v1.1.11

### Deploy: inventory variables for the public-node-local firewall mode

- The deploy tooling (Ansible `init` and `update`) can now set the chart values
  `ccm.nodeLoadBalancer.publicNodeLocal.firewallMode`, `vmFirewallMigration` and
  `vmFirewallSettleSeconds` from inventory variables
  `ccm_public_node_local_firewall_mode` (`perService` or `perVM`),
  `ccm_public_node_local_vm_firewall_migration` (`manual` or `auto`) and
  `ccm_public_node_local_vm_firewall_settle_seconds` (10-600). An operator can
  enable per-VM mode durably: a `kubectl set env` change would be reverted by the
  next `update`, and that revert would start a reverse migration.
- **No change by default.** When none of the variables is defined, the rendered
  chart values are byte-identical to v1.1.10. When any one is defined, all three
  are rendered, the others with the chart defaults (`perService`, `manual`, `10`),
  because the chart schema requires the whole block.
- Preflight rejects any other value with a clear error.
- Switching back to `perService` triggers the reverse migration. Never downgrade
  the modules while per-VM state exists. See the chart README, "Public-node-local
  firewall mode", and the deploy README.

### Tests

- `deploy/verify-static.py` checks the template, the preflight assertion and the
  documentation. A render of the template with and without the variables is
  diffed, and `helm template` accepts both renders against the chart schema.
