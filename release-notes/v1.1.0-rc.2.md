## CSI volume size limit and E2E probe tolerance

`v1.1.0-rc.2` builds on `v1.1.0-rc.1` (online CSI volume expansion).

### 2000 GiB CSI volume cap

The InSpace console offers disks up to 2000 GB. A live measurement confirmed
that InSpace `size_gb` is binary GiB: a 1Gi PVC is exactly 1073741824 bytes in
the guest and a 2Gi PVC exactly 2147483648 bytes. Before this change the
controller had no cap, so an oversized PVC reached the API and failed there.

- The controller now rejects any create or expansion above 2000 GiB with
  `OutOfRange` before calling the InSpace API.
- `--max-volume-size-gib` (default `2000`) and chart value
  `csi.maxVolumeSizeGiB` (1–2000) set a lower cap.

### E2E Node-LB continuity probe

Two live `v1.1.0-rc.1` runs failed only because one probe request timed out
after 170 and 415 successes, with no controller activity at that moment. A
path measurement from the runner found periodic SYN loss to InSpace. The probe
now fails at once on a wrong status or body, but tolerates transport timeouts
while the frontend recovers within 10 seconds (`--max-outage`). A real
datapath outage still fails the run.
