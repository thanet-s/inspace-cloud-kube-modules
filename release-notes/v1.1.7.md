## v1.1.7

### CCM

- The CCM now keeps the last known good state when the InSpace API is down or
  returns a transient error: a timeout, a canceled request, a refused or reset
  connection, an unexpected EOF, a DNS failure, HTTP 408, 429 or
  5xx, or an error body that was cut short. In v1.1.6 such a failure during the
  node load balancer sync removed the ready label from every load-balancer
  Node and cleared the `inlb-dp-*` datapath and parent Service statuses, so
  public traffic through the node load balancers stopped until the API
  recovered.
- On a transient error the node load balancer controllers (aggregate shared
  mode, the legacy per-Service helpers, and `public-node-local`) change
  nothing: they keep the Node ready labels, the Service statuses and the
  firewall assignments, log a warning, and retry with backoff. Node lifecycle
  calls (`InstanceExists`, `InstanceShutdown`, `InstanceMetadata`) already
  returned an error in this case, so no Node is deleted or tainted.
- Definite answers keep failing closed. An exact 404, an ownership or drift
  mismatch, a malformed response, and a user-initiated Service deletion still
  withdraw the datapath as before. An error that joins a transient failure with
  a definite one counts as definite.
- A `public-node-local` publication gate that fails with a definite error now
  withdraws the public address. Before, the withdrawal itself failed with
  "parent Service UID is required" and the address stayed published.
