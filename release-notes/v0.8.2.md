## Larger default worker capacity

v0.8.2 raises the aggregate limits of the default Ansible-managed Karpenter
NodePool from 32 to 128 CPU cores and from 64 GiB to 256 GiB of memory. These
limits cap total pool capacity; they do not create minimum capacity, so the
default pool continues to scale from zero in response to pending workloads.

## Upgrade notes

This patch release does not change cluster topology, immutable bootstrap
configuration, or ownership schemas. Existing clusters can upgrade the
released CRD and workload charts in place. Because real deployment inventories
are operator-owned, set `modules_version: 0.8.2`,
`karpenter_cpu_limit: "128"`, and `karpenter_memory_limit: 256Gi` in the selected
inventory before running `deploy/run.sh update` to apply the larger limits.
