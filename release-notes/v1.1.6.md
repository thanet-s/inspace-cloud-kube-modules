## v1.1.6

### RKE2

- The audited RKE2 release moves from the release candidate
  `v1.36.5-rc2+rke2r1` to the GA release `v1.36.5+rke2r1` (Kubernetes 1.36.5).
  The bundled Cilium is unchanged: rke2-cilium 1.20.200 with Cilium 1.20.2.
  The bootstrap cache serves the GA RKE2 archive and `rke2-runtime` image, and
  the control-plane bootstrap, the examples, and the E2E templates pin
  `v1.36.5+rke2r1`. All other cached RKE2 images are the same as before.
- The release candidate is no longer accepted as a new RKE2 version. The
  `rke2.version` and `rke2_version` checks (the `InSpaceCluster` and
  `InSpaceNodeClass` CRDs and validators, the controller bootstrap, and the
  `deploy` preflight) now take exact GA releases only. A NodeClass that still
  names `v1.36.5-rc2+rke2r1` fails validation, and its nodes become NotReady,
  until it names a GA release.

### Upgrading from `v1.36.5-rc2+rke2r1`

- A cluster created on `v1.36.5-rc2+rke2r1` upgrades with `deploy update`.
  Set `rke2_version: v1.36.5+rke2r1` in the inventory and run `update`. It is
  an ordinary RKE2 upgrade: the control-plane servers roll one at a time, and
  `update` still accepts the candidate as the version it upgrades from. The
  kubelet of the candidate already reports `v1.36.5+rke2r1`, so the journaled
  version in `state.json` is what records the move.
- `deploy update` moves the default NodeClass to the new release. Move every
  NodeClass that you created yourself and that still names
  `v1.36.5-rc2+rke2r1`: set `spec.rke2.version` to `v1.36.5+rke2r1`. Until
  you do, that NodeClass is NotReady and Karpenter does not launch workers from
  it.
