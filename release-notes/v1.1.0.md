## v1.1.0

`v1.1.0` is promoted from `v1.1.0-rc.7` after a full live E2E `all` run in an
isolated InSpace account. It covers everything since `v1.0.0`; the
`v1.1.0-rc.1` through `v1.1.0-rc.7` notes have the details.

### Storage

- Online CSI volume expansion for `ReadWriteOnce` PVCs (`csi-resizer`
  sidecar, `allowVolumeExpansion: true` by default).
- CSI volumes are capped at 2000 GiB (`--max-volume-size-gib`,
  `csi.maxVolumeSizeGiB`). InSpace `size_gb` is GiB.
- A resize InSpace rejects permanently fails at once with InSpace's reason
  (`InvalidArgument`).

### Platform

- Ubuntu 26.04 by default (24.04 still accepted), and bash as the login shell
  on every VM.
- RKE2 `v1.36.5-rc2+rke2r1` (Kubernetes 1.36.5) with Cilium 1.20.2. RKE2's
  GA `v1.36.5` will follow in a patch release.
- Optional, creation-time Cilium settings: `loadBalancerAlgorithm` (`maglev`)
  and `serviceTopology`. Node-LB Services default to `PreferSameNode`.
- Optional Gateway API through Cilium (`spec.network.gatewayAPI.enabled`),
  with no Traefik. Gateways work with the paid public NLB and private L2
  VIPs.
- A Cilium configuration drift check in the E2E and `deploy update`.

### Reliability

- Bootstrap no longer destroys and rebuilds every healthy cluster: only the
  bastion floating IP is probed on port 22, and control-plane internet egress
  is proven from inside. This saves about 22 minutes per `init`.
- Uncommitted cloud mutations recover automatically instead of wedging:
  Karpenter VM deletes and firewall detaches, Node-LB firewall deletes and
  relations, and bootstrap rollbacks that could leak a floating IP.
- Node-LB Services cannot claim reserved host or cluster ports.
- `deploy update` can upgrade RKE2 and refreshes the bastion bootstrap cache
  first.

### Security

- New clusters use a separate RKE2 agent token; workers never receive the
  server token.
- No API tokens on process command lines.
- Release charts, deploy, Dockerfile bases, and Python dependencies are pinned
  by digest or hash.

## Upgrade notes

- Apply the CRD chart before the workload chart.
- `loadBalancerAlgorithm`, `serviceTopology`, and `gatewayAPI` are fixed at
  cluster creation.
- Node-LB Services on reserved ports are withdrawn after the upgrade; move
  them first.
- Existing clusters keep the server token as the worker join token until an
  operator adds an agent token (see `deploy/README.md`).
- The deploy runner needs anonymous HTTPS to `api.github.com`, `github.com`,
  and `ghcr.io`.
