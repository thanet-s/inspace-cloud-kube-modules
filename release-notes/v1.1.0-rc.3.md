## Ubuntu 26.04 and a bash login shell

`v1.1.0-rc.3` builds on `v1.1.0-rc.2` (online CSI expansion, 2000 GiB CSI
cap, tolerant Node-LB continuity probe).

### Ubuntu 26.04 by default

InSpace now publishes Ubuntu 26.04 (`resolute`). New clusters and NodeClasses
use it by default; 24.04 stays accepted so existing clusters keep reconciling.

- `InSpaceCluster` `spec.controlPlane.machine.image.osVersion` and
  `InSpaceNodeClass` `spec.imageSelector.osVersion` accept `24.04` or `26.04`.
  Examples, deploy templates, and the E2E default to `26.04`.
- The bootstrap bastion now uses the control-plane Ubuntu release instead of a
  fixed 24.04.
- APT sources are no longer hardcoded to `noble`. Every bootstrap renders the
  suites from the booted release (`noble` or `resolute`) and fails on any other
  release.

### bash as the login shell on every VM

Recent InSpace images create the SSH user with `/bin/sh`. Every bootstrap path
(bastion, cache bastion, control planes, Karpenter workers, and Node-LB
workers) now switches root and every regular account from `sh`/`dash` to
`/bin/bash`, and makes bash the `useradd`/`adduser` default. The E2E asserts
this on the bastion, control planes, and worker.

## Upgrade notes

The control-plane and worker cloud-init bytes change, so the frozen
control-plane cloud-init hash is updated. Existing VMs are not rewritten in
place; they keep their current image and shell until replaced. Apply the CRD
chart from this candidate before the workload chart so the new `26.04` enum is
accepted.
